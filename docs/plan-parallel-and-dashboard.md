# План: отдельные ящики, параллельные исполнители, дашборд

Цель: несколько независимых сессий Claude (разные продукты) работают через один agentbus,
каждая может раздать сколько угодно параллельных тикетов исполнителям DeepSeek, а человек
в браузере видит, что делают агенты сейчас и что они делали раньше.

Статус: проект, не утверждён. Тикеты уходят через agentbus только после явного «да».

---

## 1. Отдельные почтовые ящики

Ящик = папка `.agentbus/<имя>/`. Изоляция сессий = разные папки.

**Bridge обслуживает все ящики.** Вместо одного `AGENTBUS_BRIDGE_AGENT` на каждом тике
обходит подпапки `.agentbus/*` (кроме dot-папок) и для каждой делает текущие
`pump_outbox / pump_inbox / pump_read`. Имя папки = имя агента, валидация
`^[a-z0-9][a-z0-9-]{1,40}$`. Маркеры доставки уже per-agent
(`state/bridge/<agent>/delivered`).

**Принудительный sender.** Сейчас `payload.setdefault("sender", agent)` — сессия может
подписаться чужим ящиком. Делать `payload["sender"] = agent` всегда. Ответ исполнителя
идёт `parent["sender"]` (`store.reply`), поэтому вернётся ровно в свой ящик.

**`cb` находит свой ящик сам**, по приоритету:
1. `AGENTBUS_SHARE` — полный путь (как сейчас);
2. `AGENTBUS_MAILBOX=<имя>` → `<root>/.agentbus/<имя>`;
3. по умолчанию `claude-<basename git toplevel от cwd>`.

Две сессии в разных продуктах разводятся без настройки. Две сессии в одном продукте —
`env` в `.claude/settings.json` проекта. `cb init [имя]` создаёт папку. `cage-claude`
продолжает работать (обратная совместимость).

## 2. Пул исполнителей и параллельные тикеты

Исполнитель — общий пул на хосте. Мастер отправляет N тикетов, каждый в **новом треде**
(свой worktree, своя ветка `agentbus/<thread_id>`), свободные слоты их разбирают.

**Worker со слотами.** `AGENTBUS_WORKER_SLOTS` (по умолчанию 1, рекомендовано 3–4):
N потоков, каждый — текущий цикл `lease → handle`. `lease_owner = <agent>#<slot>`.
Корректная остановка: SIGTERM → не брать новое, дождаться текущих (с таймаутом).

**Lease (`store.lease_message`):**
- весь lease под `pg_advisory_xact_lock(<const>)` — короткий запрос, конкуренции нет;
- **один тред — одно исполнение:** не выдавать сообщение, если в его треде уже есть
  `state='leased'` (иначе fix и note запустят два OpenCode в одном worktree; строковый
  `skip locked` этого не гарантирует);
- **справедливость:** сначала отправитель с наименьшим числом текущих lease, потом
  `created_at`;
- опционально `AGENTBUS_PER_SENDER_SLOTS` — потолок слотов на одну сессию.

**Блокировки по репозиторию в worker** (`fcntl` на `state/locks/<hash repo>`):
- вокруг `git worktree add` и операций с ветками (`.git/*.lock` при параллельных add);
- вокруг `make check` по умолчанию; проект с изолированными тестами отключает через
  `meta.checks_parallel: true`.

**Инструменты мастера в `cb`:**
- **квитанции:** bridge после приёма пишет `sent/<stem>.receipt.json` с `id`, `thread_id`;
  `cb send --wait-id` ждёт её и печатает. Сейчас мастер не знает id отправленного;
- **`cb wait m_1 m_2 … [--any|--all] [--timeout N]`** — ждёт ответы по `parent_id`;
- **`meta.ticket`** (`"T2.3"`) — показывается в `cb inbox` и в дашборде;
- **структурный вердикт:** `cb reply --kind verdict --accept|--rework "..."` →
  `meta.decision`. Нужен для статистики приёмки с первого ревью.

**Вне agentbus (остаётся мастеру):** зависимости между тикетами (зависимый не отправляется,
пока предыдущий не принят) и merge (ветки от одного `base_ref`, мастер мержит по очереди,
конфликт → fix-тикет в тред проигравшей ветки).

## 3. Дашборд наблюдаемости

Локальная веб-страница на хосте: что агенты делают сейчас и полная история.
Только чтение. Отдаётся тем же FastAPI, `http://127.0.0.1:8787/ui/`.

### Данные

Почти всё уже есть: `messages`, `threads`, артефакты (`run.log`, `patch.diff`,
`checks.txt`). Не хватает:

- **таблица `events`** (append-only): `id, at, message_id, thread_id, actor, kind, data
  jsonb`. Пишется в `store` при создании сообщения, lease, reply, смене состояния, reap
  просроченного lease. Из неё — таймлайн треда, время в очереди, время исполнения,
  повторы;
- **таблица `workers`**: `id (<agent>#<slot>), host, pid, model, harness, state
  (idle|busy|stopping), message_id, started_at, heartbeat_at`. Upsert при старте слота,
  на каждом lease и heartbeat. Слот без heartbeat > 2×TTL показывается как «пропал»;
- **поля в meta результата:** `model`, `harness` (сейчас `opencode`), сумма токенов по
  **всем** `step_finish` (сейчас worker берёт только последний — баг), число tool calls;
- **`pg_notify('agentbus', ...)`** из `store` после записи события — источник живых
  обновлений без опроса.

### Живой лог исполнителя

`run.log` — JSON-события OpenCode: `step_start`, `tool_use` (`part.tool`,
`part.state.input`, `status`), `text`, `step_finish` (токены, кэш). Сейчас worker пишет его
буферизованно и сбрасывает в конце — нужен `flush()` на каждую строку. Пока задача идёт,
лог лежит в `artifacts/<message_id>/`, после — переносится под id ответа; API ищет в обоих
местах.

Парсер в API превращает событие в строку ленты: `12:04:31 shell  make check  ✓`,
`12:04:40 edit  src/x.py`, `12:05:02 💬 текст агента`. Сырой JSON — по клику.

### Эндпоинты (все под токеном, только GET)

- `GET /v1/overview` — слоты, очереди по ящикам, счётчики;
- `GET /v1/mailboxes`, `GET /v1/mailboxes/{name}/threads`;
- `GET /v1/threads/{id}/timeline` — сообщения + события + артефакты;
- `GET /v1/messages/{id}/log?after=<n>` — распарсенная лента с курсора;
- `GET /v1/stats?group=mailbox|repo|model&from=&to=`;
- `GET /v1/stream` — SSE: события из `LISTEN agentbus` + хвост логов занятых слотов.

### Страницы

1. **Сейчас** — карточка на каждый слот: свободен / занят (ящик, тикет, репо, сколько
   идёт, последний tool call, токены). Ниже очередь по ящикам. Обновляется через SSE.
2. **Ящики** — сессии Claude: сколько тикетов отправлено, в работе, ждёт ревью, принято.
3. **Тред** — таймлайн `task → result → verdict → fix → …`; у каждого результата —
   дифф (подсветка, по файлам), `checks.txt`, лента `run.log`, длительность, токены.
   У занятого треда лента идёт в реальном времени.
4. **История** — таблица всех тредов с фильтрами (ящик, репо, состояние, модель, текст).
5. **Статистика** — по ящику / репо / модели: тикеты, медиана времени в очереди и
   исполнения, токены, доля принятых с первого ревью, среднее число циклов доработки,
   таймауты и сбои. Это же — инструмент A/B сравнения harness (OpenCode / DeepSeek
   Harness / Claude Code): у каждого результата есть `model` и `harness`.

### Реализация

- Один `ui/index.html` + ванильный JS (или htmx) из `src/agentbus/ui/`, без сборки и
  npm; FastAPI отдаёт статику. Подсветка диффа — небольшой самописный рендер
  unified diff.
- SSE через `StreamingResponse`; `LISTEN` в отдельном соединении psycopg.

### Безопасность

- Bind только `127.0.0.1` (уже так).
- Вход: `GET /ui/login?token=…` ставит HttpOnly SameSite=Strict cookie, дальше UI ходит
  с ней. Bearer для `cb`/`ab`/worker не меняется.
- Проверка `Host` ∈ {`127.0.0.1:8787`, `localhost:8787`} — защита от DNS rebinding.
- v1 только чтение. Кнопки «отменить тикет» / «убить прогон» — отдельным шагом
  после v1; merge и деплой в дашборде не появляются никогда.

### Хранение

Артефакты и `events` растут. `make prune KEEP=<N тредов>` — удалить артефакты и worktree
закрытых тредов сверх последних N; строки в БД оставить (они маленькие).

## 4. Риски, которые проверяет smoke

- Параллельные `opencode run`: общее состояние в `~/.local/share/opencode` — smoke
  обязан реально запустить два одновременно.
- Rate limit DeepSeek на 3–4 слотах: 429 сейчас попадает в `errors` без ретрая.
- OpenCode сам гоняет тесты внутри прогона — lock на `make check` это не покрывает.
  Для проектов с общими ресурсами в тестах — `AGENTBUS_REPO_SLOTS=1`.
- SSE + LISTEN держат соединение к Postgres на каждого зрителя — ограничить одним
  общим слушателем с fan-out в процессе API.

## 5. Тикеты

| #  | Тикет | Зависит |
|----|-------|---------|
| T1 | bridge: обход всех ящиков, принудительный sender, квитанции `sent/*.receipt.json` + тесты | — |
| T2 | `cb`: выбор ящика, `init`, `send --wait-id`, `wait --any/--all`, `ticket` в inbox, `--accept/--rework` + тесты | T1 |
| T3 | `store` lease: advisory lock, сериализация треда, справедливость, потолок на отправителя, `owner` + тесты на Postgres | — |
| T3b | миграция `events` + `workers`, запись событий в `store`, `pg_notify` + тесты | — |
| T4 | worker: N слотов, `lease_owner` со слотом, регистрация в `workers`, locks по репо, построчный flush `run.log`, сумма токенов, `model`/`harness` в meta, корректная остановка + тесты | T3, T3b |
| T5 | API для дашборда: GET-эндпоинты, парсер `run.log`, SSE с общим LISTEN, cookie-вход, проверка Host + тесты | T3b |
| T6 | UI v1: страницы «Сейчас», «Тред» (таймлайн, дифф, живая лента) | T5 |
| T7 | UI v1: «Ящики», «История», «Статистика» | T5 |
| T8 | SKILL.md (параллельная раздача тикетов, вердикты), README, `.env.example`, systemd, `make prune`, smoke: 2 ящика × 2 параллельных тикета + дашборд показывает оба | T1–T7 |

Порядок, пока слот один: T1 → T3 → T2 → T3b → T4. После T4 можно включить 2 слота, и T5, затем
T6 ‖ T7, идут параллельно — первая проверка пула на самом agentbus.
