# T1 — bridge обслуживает все почтовые ящики

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 1. Сейчас bridge обслуживает один
ящик (`AGENTBUS_SHARE` = папка `.agentbus/cage-claude`). Нужно, чтобы один процесс bridge
обслуживал все папки внутри `.agentbus/`, и каждая папка была отдельным агентом.

## Что сделать

### 1. Корень шара и обнаружение ящиков (`src/agentbus/config.py`, `src/agentbus/bridge.py`)

- `BridgeSettings` получает поле `share_root: str`:
  - `AGENTBUS_SHARE_ROOT`, если задана;
  - иначе родитель `AGENTBUS_SHARE` (обратная совместимость: в текущем env
    `AGENTBUS_SHARE=/home/ruslan/personal/.agentbus/cage-claude` → корень
    `/home/ruslan/personal/.agentbus`);
  - если не задано ни то, ни другое — `RuntimeError` с понятным текстом.
- Имя ящика валидно, если матчит `^[a-z0-9][a-z0-9-]{1,40}$`. Папки с другими именами
  (включая начинающиеся с точки) пропускаются молча; невалидные имена без точки —
  одна строка в лог при первом обнаружении, не на каждом тике.
- Новый класс `MultiBridge(settings, api)`:
  - `discover()` — список валидных подпапок `share_root`, отсортированный;
  - держит кэш `dict[str, Bridge]`; новая папка, появившаяся во время работы,
    подхватывается на следующем тике без рестарта;
  - `run_once()` вызывает `run_once()` каждого `Bridge` и возвращает суммы
    `(sent, delivered, acked)`; исключение в одном ящике логируется и не мешает
    остальным.
- Класс `Bridge` остаётся однo-ящиковым. Его конструктор берёт путь ящика и имя агента
  явно (например `Bridge(settings, api, mailbox_dir: Path, agent: str)`), а не из
  `settings.share_dir` / `settings.agent`. Имя агента = имя папки.
- `AGENTBUS_BRIDGE_AGENT` больше не используется: если задана и не совпадает ни с одной
  папкой — одна строка-предупреждение в лог при старте. Поле `agent` из `BridgeSettings`
  можно удалить, если на него больше ничего не ссылается.
- `main()` запускает `MultiBridge`; строка старта логирует корень и найденные ящики.

### 2. Принудительный отправитель

В `Bridge.pump_outbox` заменить `payload.setdefault("sender", self.agent)` на
`payload["sender"] = self.agent`. Если в файле был другой `sender` — сообщение всё равно
отправляется, но от имени ящика (подменить себя на чужой ящик нельзя).

### 3. Квитанции об отправке

После успешного `POST /v1/messages` (200/201) bridge, **до** переноса файла в `sent/`,
пишет атомарно (tmp + `os.replace`) `sent/<stem>.receipt.json`:

```json
{"file": "<имя исходного файла>", "id": "m_...", "thread_id": "t_...",
 "kind": "task", "recipient": "local-opencode", "created_at": "..."}
```

`<stem>` — stem исходного файла из outbox (тот, что стал ключом идемпотентности).
Повторная доставка того же файла (ответ API на дубль идемпотентности) переписывает
квитанцию теми же данными — это нормально.

### 4. Документация

- `README.md`, раздел «Cage без сети»: один bridge на все ящики, ящик = папка в
  `.agentbus/`, новая папка подхватывается сама, `AGENTBUS_SHARE_ROOT`, квитанции.
- `.env.example`: добавить `AGENTBUS_SHARE_ROOT` с комментарием, пометить
  `AGENTBUS_BRIDGE_AGENT` как устаревшую.

## Чего НЕ делать

- Не трогать `bin/cb`, `worker.py`, `store.py`, `api.py`, миграции — это другие тикеты.
- Не менять формат `inbox/<id>/message.json` и логику `pump_inbox` / `pump_read`
  (кроме того, что агент берётся из конструктора).
- Не добавлять зависимостей.

## Тесты (`tests/test_bridge.py`)

Существующие тесты остаются зелёными (поправить только вызов конструктора / фикстуру).
Новые:

1. Два ящика `alpha` и `beta`: каждый кладёт task → оба сообщения в очереди с
   `sender` = имя своей папки; ответ исполнителя на задачу `alpha` доставляется только
   в `alpha/inbox`, в `beta/inbox` пусто.
2. Папка `gamma`, созданная после первого `run_once()`, обслуживается на следующем.
3. Папки `.hidden`, `Bad_Name`, `x` (слишком короткое) не обслуживаются: `outbox`
   внутри них не трогается, `sent/` не создаётся.
4. Файл в outbox с `"sender": "beta"` в ящике `alpha` → сообщение от `alpha`.
5. После отправки в `sent/` лежит `<stem>.receipt.json` с `id` и `thread_id`,
   совпадающими с сообщением в API.
6. Ошибка в одном ящике (например, `inbox` — файл, а не каталог) не мешает другому
   ящику отправить своё сообщение.
7. `BridgeSettings.from_env`: корень из `AGENTBUS_SHARE_ROOT`; корень как родитель
   `AGENTBUS_SHARE`; ни одной переменной → `RuntimeError`.

## Критерии приёмки

- `make check` зелёный (ruff check, ruff format --check, pytest).
- Все 7 новых тестов есть и проходят; существующие не удалены и не ослаблены.
- Изменены только файлы из списка выше.
- В отчёте: список изменённых файлов, вывод `make check` (хвост), и явно — как теперь
  запускать bridge с текущим `~/.config/agentbus/env` без его правки.
