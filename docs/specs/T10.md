# T10 — роутер UI понимает query в хэше; убрать shim из страниц T7

Контекст: ревью T7. Роутер `src/agentbus/ui/app.js` сопоставляет весь хэш с шаблоном
(`^/history/?$`), поэтому `#/history?mailbox=…` и `#/stats?group=…` давали «Не найдено».
T7 не мог трогать `app.js` и обошёл это shim'ом в `pages/history.js` и `pages/stats.js`
(временно убирает query из хэша, потом возвращает через `replaceState`).

## Что сделать

- `app.js`: хэш делится на путь и query (`#/history?mailbox=a&state=review` → путь
  `/history`, query `URLSearchParams`). Сопоставление шаблонов — только по пути.
  В `render(root, params, ctx)` добавить `params.query` (обычный объект
  `{mailbox: "a", state: "review"}`) и в `ctx` — `setQuery(obj, {replace})`: обновляет
  query в хэше (`pushState`, или `replaceState` при `replace: true`) **без** повторного
  рендера страницы и вызывает подписчиков `ctx.onQuery(fn)`; переход назад/вперёд по
  истории с изменением только query тоже вызывает `onQuery`, а не полный ререндер.
  Смена пути — полный рендер, как сейчас.
- `pages/history.js`, `pages/stats.js`: убрать shim, читать фильтры из `params.query`,
  менять через `ctx.setQuery`, реагировать на `ctx.onQuery`. Поведение для пользователя
  не меняется (ссылки с фильтрами сохраняемы, Back возвращает прошлый фильтр, поиск не
  теряет фокус).
- `pages/mailboxes.js`: ссылка на историю — как сейчас (`#/history?mailbox=…`).

## Проверка

- `tests/test_ui.py`: `app.js` содержит `setQuery` и `onQuery`; в `history.js` и
  `stats.js` больше нет `replaceState` (признак shim).
- `node --check` всех файлов.
- Вручную в браузере (как в T6/T7): прямая загрузка `#/history?mailbox=…&state=review`,
  смена фильтров, Back, `#/stats?group=repo`, переключение групп; консоль без ошибок.
