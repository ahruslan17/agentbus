# T11 — состояние очереди в ящике: `status.json` и `cb status`

Контекст: Claude в VM видит только ящик (`.agentbus/<mailbox>/`). API на хосте ему
недоступен (ни сети, ни токена — и так и должно остаться). Сейчас после `cb send` он знает
лишь «поставлено в очередь» (квитанция) и «пришёл ответ» (inbox). Взял ли worker задачу,
что он сейчас делает, сколько впереди в очереди — не видно. Нужно, чтобы мост
публиковал это в ящик.

## 1. API: `GET /v1/mailboxes/{name}/status` (`store.py`, `api.py`)

`store.mailbox_status(conn, mailbox, *, lease_ttl_seconds)` → dict:

- `workers`: все слоты (`id`, `state`, `model`, `harness`, `heartbeat_at`, `stale`,
  `message_id`). Для слота, занятого сообщением **этого** ящика, — ещё `ticket`
  (`meta.ticket`) и `thread_id`; для чужих — только `sender` (чей ящик), без текста/тикета.
- `queues`: как в `overview` (по recipient: queued/leased).
- `pending`: сообщения, отправленные этим ящиком (`sender = mailbox`), в состоянии
  `queued`/`leased`, плюс последние 20 завершённых (`done`/`failed`/`cancelled`) за
  сутки. Поля: `id`, `thread_id`, `kind`, `ticket`, `state`, `attempt`, `lease_owner`,
  `lease_until`, `created_at`, `updated_at`; для `queued` — `queue_position`
  (сколько сообщений того же recipient в `queued` создано раньше, +1; это оценка,
  справедливость lease может её менять — так и назвать в cb);
  `result_id` — id ответа (`kind='result'`, `parent_id = id`), если есть.
- `events`: последние 30 событий по тредам этого ящика (тред, где есть task от него).

Эндпоинт под тем же `guard`. Имя ящика валидировать как в bridge (`MAILBOX_NAME`).

## 2. Мост пишет `<mailbox>/status.json` (`bridge.py`, `config.py`)

- Раз в `AGENTBUS_STATUS_INTERVAL` секунд (по умолчанию 5; 0 — выключить) для каждого
  ящика: запрос из п. 1 → `status.json` с полями из ответа + `generated_at` (UTC ISO) +
  `bridge`: `{"pid", "interval"}`. Запись атомарная: временный файл в том же каталоге +
  `os.replace`. Для `leased` сообщений этого ящика добавить `log_tail` — последние 15
  строк `run.log` (через `/v1/messages/{id}/log`, только текст строк, не больше 4 КиБ на
  сообщение).
- Если API недоступен — переписать `status.json` с `{"generated_at", "error": "..."}`,
  не роняя цикл (троттлинг лога как у ошибок ящика).
- Ошибка статуса не мешает pump outbox/inbox/read.

## 3. `cb status [--json] [--log] [id ...]` (`bin/cb`)

- Читает `status.json` своего ящика (разрешение ящика как у остальных команд).
- Первой строкой — свежесть: `status: 3s ago`; если старше `max(30, 6*interval)` или файла
  нет — `status is stale (Ns) — bridge or API down?` и exit code 2.
- Слоты: `local-opencode#0 busy m_… [OPS-prune] 4m` / `idle` / `stale`.
- Мои сообщения: `m_… [T11] leased by local-opencode#1, attempt 1, 6m` /
  `queued, ~2nd in line` / `done → result m_…`.
- `id ...` — только эти сообщения; `--log` — показать `log_tail` для leased;
  `--json` — сырой файл.
- `cb wait` (без изменения интерфейса): если есть `status.json`, при смене состояния
  ожидаемого сообщения печатать одну строку в stderr (`m_… queued → leased by …`).
- `cb env`: добавить строку с возрастом `status.json`.

## Тесты

- `tests/test_dashboard_api.py` (или новый `tests/test_status.py`): `mailbox_status` —
  свои queued/leased/done попадают в `pending` с `queue_position` и `result_id`; чужой
  ящик не видит тикет/текст чужих сообщений (только `sender` в слоте); невалидное имя →
  422/400.
- `tests/test_bridge.py`: `status.json` пишется атомарно и раз в interval (время
  подменить); при ошибке API — файл с `error`, outbox/inbox продолжают работать;
  `interval=0` — файла нет.
- `tests/test_cb.py`: `cb status` на подложенном `status.json` — вывод, exit 2 для
  старого файла и отсутствующего файла, `--json`, фильтр по id; `cb wait` печатает
  переход состояния.

## Критерии приёмки

- `make check` зелёный, новые тесты есть, существующие не ослаблены.
- Изменены только файлы из списка. UI (`src/agentbus/ui/`) не трогать. Не коммитить.
- В `status.json` нет токена, тел сообщений и данных чужих ящиков кроме `sender`
  занятого слота.
