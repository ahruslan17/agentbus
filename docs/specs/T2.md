# T2 — `cb`: свой ящик, id отправленного, ожидание нескольких ответов, вердикты

Контекст: `docs/plan-parallel-and-dashboard.md`, разделы 1–2. Опирается на T1: bridge
обслуживает все папки `.agentbus/*` и пишет квитанции `sent/<stem>.receipt.json`
(`id`, `thread_id`, `kind`, `recipient`, `created_at`, `file`).

`bin/cb` работает внутри VM: **только стандартная библиотека python3**, без сети.

## Что сделать

### 1. Выбор ящика (`share()`)

Порядок:
1. `AGENTBUS_SHARE` — полный путь к папке ящика (как сейчас);
2. `AGENTBUS_MAILBOX=<имя>` → `<корень>/<имя>`;
3. если cwd внутри git-репозитория (поиск `.git` вверх по дереву, без вызова `git`) —
   `claude-<имя корня репозитория>`; имя нормализуется: lower-case, всё кроме
   `[a-z0-9-]` → `-`, схлопнуть повторы `-`, обрезать `-` по краям, до 33 символов;
4. иначе `cage-claude` (обратная совместимость).

`<корень>` = `AGENTBUS_SHARE_ROOT`, иначе `<...>/.agentbus` рядом с checkout'ом `cb`
(как сейчас вычисляется `here.parents[2] / ".agentbus"`).

Итоговое имя валидируется `^[a-z0-9][a-z0-9-]{1,40}$` (как в bridge), иначе понятная
ошибка. `send`, `reply` и `init` создают папку ящика, если её нет; остальные команды на
отсутствующий ящик дают ошибку, как сейчас.

- `cb init [имя]` — создать ящик (`outbox/ inbox/ sent/ read/`) и напечатать путь.
- `cb env` дополнительно печатает `mailbox` (имя) и `source` (какой из пунктов 1–4
  сработал).

### 2. id отправленного сообщения

`send` и `reply` после записи в outbox ждут квитанцию `sent/<stem>.receipt.json`
(опрос раз в 0.5 с, до `--wait-id <сек>`, по умолчанию 15; `--wait-id 0` — не ждать).
Вывод — JSON как сейчас плюс `id` и `thread_id` из квитанции. Если квитанции нет за
отведённое время — печатаем то, что есть, предупреждение в stderr, код выхода 0.
Если файл оказался в `failed/` — печатаем текст ошибки из `.error`, код выхода 1.

### 3. `cb wait`

```
cb wait <id> [<id> ...] [--all] [--timeout <сек>]
```

Ждёт в `inbox/` сообщения, у которых `parent_id` ∈ переданных id (id отправленных task /
verdict). По умолчанию возвращается при первом пришедшем (`--any`-поведение), с `--all` —
когда пришли ответы на все. Опрос раз в 2 с. Для каждого найденного печатает строку:

```
<parent_id> -> <id>  [<kind>]  <ticket>  checks=<ok|fail|->  timeout=<true|false>
```

`--timeout` по умолчанию 3600; по таймауту — что успело прийти, и код выхода 2.
Ответ, уже лежащий в `inbox/` или `read/` на момент вызова, считается пришедшим.

### 4. Тикет в выводе

`meta.ticket` отправленного сообщения показывается в `cb inbox` и `cb show --text`
для ответов на него. Связь: `ответ.parent_id` → квитанция с таким `id` в `sent/` →
исходный файл `sent/<file>` → `meta.ticket`. Для цепочки task → result → verdict →
result тикет берётся из ближайшего предка, у которого он есть (вердикт, отправленный
через `reply`, наследует `ticket` из сообщения, на которое отвечает, если не задан явно).

### 5. Решения ревью

- `cb reply <id> --kind verdict ...` по умолчанию добавляет `meta.decision = "rework"`.
- `cb accept <id> [--note "..."]` — принять результат: пишет
  `inbox/<id>/decision.json` = `{"decision": "accept", "note": "..."}` и переносит папку в
  `read/` (как `cb read`).
- bridge (`pump_read`): если в `read/<id>/decision.json` есть `decision`, то в
  `POST /v1/messages/{id}/state` уходит `note = "accept"` или `"accept: <note>"` вместо
  `"read in the VM"`. Без файла — как сейчас.

### 6. Документация

Docstring `cb` и README (раздел про `cb`): выбор ящика, `init`, `wait`, `accept`,
id в выводе `send`.

## Чего НЕ делать

- Никаких сторонних модулей и сетевых вызовов в `cb`.
- Не трогать `worker.py`, `store.py`, `api.py`, миграции.
- В bridge менять только `pump_read` (пункт 5).
- Не переименовывать существующие команды и флаги.

## Тесты

`tests/test_cb.py` вызывает `cb` через `subprocess` (`sys.executable bin/cb ...`) с
временным корнем (`AGENTBUS_SHARE_ROOT`) и подготовленными файлами — без API и Postgres,
квитанции и ответы раскладывает сам тест.

1. Выбор ящика: `AGENTBUS_SHARE` > `AGENTBUS_MAILBOX` > git-корень (`My_Repo.v2` →
   `claude-my-repo-v2`) > `cage-claude`; `cb env` печатает `mailbox` и `source`.
2. Невалидный `AGENTBUS_MAILBOX` → ненулевой код и сообщение.
3. `send` с квитанцией (тест пишет её из фонового потока через ~1 с) → в выводе `id`,
   `thread_id`; без квитанции при `--wait-id 1` → код 0 и предупреждение; файл в
   `failed/` с `.error` → код 1 и текст ошибки.
4. `wait a b` → возвращается после первого ответа; `wait a b --all` — после обоих;
   по таймауту код 2.
5. `inbox` показывает `ticket` ответа через цепочку квитанций, включая
   task → result → verdict → result.
6. `reply --kind verdict` кладёт `meta.decision = "rework"`; `accept` создаёт
   `read/<id>/decision.json`.

`tests/test_bridge.py`: `pump_read` с `decision.json` → у сообщения в API
`meta.state_note == "accept: <note>"`; без файла — `"read in the VM"`.

## Критерии приёмки

- `make check` зелёный (ruff проверяет `src tests`; `bin/cb` прогнать через
  `uv run ruff check bin/cb` вручную и привести в порядок).
- Все тесты выше есть и проходят; существующие не ослаблены.
- Изменены только файлы из списка.
- В отчёте: хвост `make check`, вывод `ruff check bin/cb`, пример сессии
  `init → send → wait → accept` (из теста или ручного прогона).
