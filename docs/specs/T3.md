# T3 — lease для пула исполнителей

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 2 («Lease»). Сейчас
`store.lease_message` выдаёт самое старое `queued` сообщение получателю через
`for update skip locked`. Для нескольких параллельных исполнителей этого мало: два слота
могут одновременно взять два сообщения одного треда (два OpenCode в одном worktree), а
одна сессия с длинной очередью забирает все слоты.

## Что сделать

### 1. `store.lease_message` (`src/agentbus/store.py`)

Новая сигнатура (keyword-only):

```python
def lease_message(conn, *, agent: str, ttl_seconds: int,
                  kinds: tuple[str, ...] | None = None,
                  owner: str | None = None,
                  per_sender_limit: int = 0) -> dict | None
```

- `owner` пишется в `lease_owner`; по умолчанию `agent` (как сейчас).
- Весь lease (reap + выбор + update) выполняется в одной транзакции под
  `select pg_advisory_xact_lock(<константа>)`. Константу вынести в модуль
  (`LEASE_LOCK_KEY`). `skip locked` после этого можно оставить или убрать — на выбор,
  но поведение должно быть корректным.
- **Сериализация треда:** не выдавать сообщение, если в его треде (`thread_id`) уже есть
  сообщение в состоянии `leased` (любого получателя). Сообщения без `thread_id`
  не ограничиваются.
- **Справедливость:** среди подходящих сообщений сначала то, у отправителя (`sender`)
  которого меньше всего сообщений в состоянии `leased` для этого же `recipient`; при
  равенстве — самое старое по `created_at`, затем по `id`.
- **Потолок на отправителя:** если `per_sender_limit > 0`, не выдавать сообщения
  отправителя, у которого уже `>= per_sender_limit` сообщений `leased` для этого
  `recipient`.
- Существующая семантика сохраняется: фильтр `kinds`, `attempt + 1`, `lease_until`,
  возврат строки или `None`.

Транзакционность: соединение из `store.connect` работает с autocommit=False, и
транзакция коммитится при выходе из `with`. Убедись, что advisory xact lock держится
ровно до коммита lease и что API-эндпоинт lease коммитит после каждой попытки (сейчас
`with store.connect(...)` внутри цикла — так и оставить).

### 2. Настройка и API (`src/agentbus/config.py`, `src/agentbus/api.py`)

- `Settings.per_sender_leases: int` из `AGENTBUS_PER_SENDER_LEASES`, по умолчанию 0
  (без ограничения).
- `POST /v1/inbox/{agent}/lease` принимает необязательный query `owner`
  (строка ≤ 64 символов, `^[A-Za-z0-9._#-]+$`, иначе 422) и передаёт его в store вместе с
  `per_sender_limit=settings.per_sender_leases`.

### 3. `.env.example`

`AGENTBUS_PER_SENDER_LEASES=0` в блок API с комментарием.

## Тесты

Существующие тесты остаются зелёными. Новые (через API или напрямую через `store` с
`TEST_URL`):

1. Два сообщения одного треда (task + note через `thread_id`) для `local-opencode`:
   первый lease выдаёт одно, второй — `204`/`None`; после `reply` на первое второй lease
   выдаёт второе.
2. Сообщения двух разных тредов выдаются двум lease подряд.
3. Справедливость: отправитель A кладёт 3 задачи, затем B — 1. Lease #1 → A (самое старое),
   lease #2 → B (у A уже один leased), lease #3 → A.
4. `per_sender_limit=1`: A кладёт 2 задачи в разных тредах → второй lease `None`, пока
   первая не закрыта.
5. `owner="local-opencode#2"` записывается в `lease_owner`; невалидный `owner` → 422.
6. Гонка: 8 потоков одновременно вызывают `store.lease_message` (каждый со своим
   соединением) над 4 сообщениями одного треда и 4 сообщениями разных тредов — в итоге
   выдано ровно 5 сообщений (1 из общего треда + 4), ни одно не выдано дважды.
7. Просроченный lease (как в `test_expired_lease_is_requeued`) не блокирует тред: после
   reap сообщение треда снова выдаётся.

## Критерии приёмки

- `make check` зелёный.
- Все 7 новых тестов есть и проходят, существующие не удалены и не ослаблены.
- Изменены только файлы из списка (плюс `tests/test_lease.py` / `tests/conftest.py`
  по правилам выше).
- В отчёте: итоговый SQL lease целиком и хвост `make check`.
