# T3c — своя тестовая БД на каждый прогон pytest

Проблема: все прогоны тестов используют одну БД `agentbus_test`. С двумя слотами
исполнители гоняют `make check` в разных worktree одновременно и ломают друг другу
тесты (чужие сообщения в очереди, `truncate` посреди чужого теста). Так упал `make check`
у T5, пока параллельно шёл T4b.

## Что сделать (`tests/conftest.py`)

- Если `AGENTBUS_TEST_DATABASE_URL` задана — использовать её как сейчас (ничего не
  создавать и не удалять сверх текущего поведения).
- Иначе `TEST_URL` вычисляется **на уровне модуля** (его импортируют `test_events.py`,
  `test_lease.py`): база `postgresql://agentbus:agentbus@127.0.0.1:5455` (как сейчас) +
  имя `agentbus_test_<pid>_<6 hex случайных>`.
- Сессионная фикстура `database`: создаёт эту БД (как сейчас создаёт `agentbus_test`),
  применяет схему; по окончании сессии — `drop database ... with (force)` только для
  БД, созданной этим прогоном. Ошибка удаления — warning, не падение.
- Поведение при недоступном Postgres — как сейчас (`pytest.skip`).
- Если где-то ещё в тестах захардкожено имя `agentbus_test` — перевести на `TEST_URL`.

## Тесты

`tests/test_conftest_db.py`:
1. `TEST_URL` без env содержит `agentbus_test_<pid>_`.
2. БД из `TEST_URL` существует во время сессии.
3. Проверка изоляции: подпроцессом запустить `pytest tests/test_queue.py -q` дважды
   **параллельно** (два `subprocess.Popen`, env без `AGENTBUS_TEST_DATABASE_URL`) — оба
   с кодом 0; после их завершения их БД удалены (в `pg_database` нет имён с их pid).

## Файлы

`tests/conftest.py`, `tests/test_conftest_db.py` (новый), другие `tests/*.py` — только
если там захардкожено имя БД.

## Критерии приёмки

- `make check` зелёный; три теста есть и проходят.
- Изменены только файлы из списка. Не коммить.
- В отчёте: хвост `make check`, список БД `agentbus_test%` до и после прогона.
