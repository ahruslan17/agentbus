# T4 — worker: N параллельных слотов

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 2. Опирается на T3 (lease с
`owner`, один lease на тред, справедливость) и T3b (`PUT /v1/workers/{id}`).
Сейчас `src/agentbus/worker.py` — один цикл `lease → handle → reply`: пока идёт один
тикет (до 40 минут), остальные ждут.

## Что сделать (`src/agentbus/worker.py`, `src/agentbus/config.py`)

### 1. Слоты

- `WorkerSettings` получает `slots: int` из `AGENTBUS_WORKER_SLOTS` (по умолчанию 1,
  минимум 1) и `stop_grace_seconds: int` из `AGENTBUS_STOP_GRACE` (по умолчанию
  `task_timeout_seconds`).
- `main()` запускает `slots` потоков. Слот `i` (0..N-1) — объект `Slot` со своим
  `Client` и `owner = f"{agent}#{i}"`; цикл слота — текущий цикл `main()`:
  `lease(wait=60, owner=owner)` → `handle(...)` → снова.
- `Client.lease` передаёт `owner` в query.
- `Client` принимает необязательный готовый `httpx.Client` (для тестов —
  `fastapi.testclient.TestClient`), иначе создаёт свой как сейчас.

### 2. Реестр

Каждый слот сообщает о себе через `PUT /v1/workers/{owner}` (в URL `#` → `%23`):
`agent`, `host` (`socket.gethostname()`), `pid` (`os.getpid()`), `model`,
`harness = "opencode"`, `state`, `message_id`.
- при старте слота и после каждого пустого lease — `idle`;
- после получения сообщения — `busy` с `message_id`;
- во время исполнения — в существующем `Heartbeat` вместе с heartbeat сообщения;
- при остановке — `stopping`, по выходу слота — `stopped`.

Ошибка реестра логируется и **никогда** не роняет слот и задачу.

### 3. Блокировки по репозиторию

`fcntl.flock` на `<state_dir>/locks/<sha1(абсолютный путь repo)[:16]>.lock`:
- вокруг `prepare_worktree` (параллельный `git worktree add` в один репозиторий падает
  на `.git/*.lock`);
- вокруг `run_checks`, если в `meta` сообщения нет `"checks_parallel": true`.

Отдельная функция-контекстный менеджер `repo_lock(settings, repo, name)`; лок
освобождается при исключении.

### 4. Остановка

SIGTERM / SIGINT (обработчик ставится в главном потоке):
- выставить общий `stop` event; слоты не берут новые сообщения (проверка перед
  каждым lease; длинный lease при остановке — допустимо дождаться его возврата,
  но слот не должен брать новую задачу, если `stop` выставлен);
- текущие задачи дорабатывают; главный поток ждёт слоты до `stop_grace_seconds`;
- по истечении — убить process group запущенных `opencode` (храните `Popen` в слоте)
  и выйти; незавершённые сообщения вернутся в очередь сами по истечении lease.
- лог: `stopping, waiting for N running tasks`, `stopped`.

### 5. Тестируемость

- `run_opencode` не меняет поведение, но бинарь берётся из `settings.opencode_bin` —
  тесты подставляют фейковый скрипт.
- `main()` разбить так, чтобы тест мог запустить слоты без сигналов:
  `run_slots(settings, stop: threading.Event, http=None) -> list[threading.Thread]`.

## Тесты — новый `tests/test_worker.py`

Используют `client` (TestClient) из conftest как `http` для `Client`; временный git-репо
в `tmp_path` (init + один коммит), `AGENTBUS_REPOS` = `tmp_path`; фейковый `opencode` —
исполняемый python-скрипт в `tmp_path`, который: дописывает `start <ts> <cwd>` /
`end <ts>` в общий файл-журнал, спит `FAKE_SLEEP` секунд (env, по умолчанию 1),
создаёт файл в cwd и печатает JSON-события `text` (с `time.end`) и `step_finish`.

1. 2 слота, 2 задачи в разных тредах одного репо → обе получили `result`, интервалы
   `start..end` в журнале **пересекаются**, оба worktree созданы (лок на worktree add
   работает).
2. 2 слота, task + note в одном треде → интервалы **не пересекаются**.
3. 1 слот, 2 задачи → не пересекаются (поведение по умолчанию не изменилось).
4. Реестр: во время работы `GET /v1/workers` показывает `local-opencode#0` и `#1`,
   один `busy` с `message_id`; после остановки оба `stopped`.
5. Остановка: `stop.set()` во время задачи → задача доходит до `result`, новая задача,
   положенная после `stop`, остаётся `queued`.
6. `repo_lock`: два потока берут лок одного репо — вход строго по очереди; разных
   репо — параллельно.
7. Ошибка реестра (сервер отвечает 500 на `PUT /v1/workers/...`, подмена через
   monkeypatch) не мешает задаче получить `result`.

Тесты не должны идти дольше ~20 с суммарно; `FAKE_SLEEP` маленький.

## Чего НЕ делать

- Не менять `build_prompt`, формат отчёта, `collect_diff`, разбор событий, `run_checks`
  (кроме обёртки локом) — это T4b.
- Не трогать `store.py`, `api.py`, `bridge.py`, `bin/cb`, миграции.
- Не добавлять зависимостей.

## Файлы

`src/agentbus/worker.py`, `src/agentbus/config.py`, `tests/test_worker.py`,
`.env.example` (`AGENTBUS_WORKER_SLOTS`, `AGENTBUS_STOP_GRACE` в блок worker),
`deploy/agentbus-worker.service` (если нужно: `KillSignal=SIGTERM`,
`TimeoutStopSec` ≥ grace).

## Критерии приёмки

- `make check` зелёный, все 7 тестов есть и проходят, существующие не ослаблены.
- Изменены только файлы из списка.
- **Не коммить** — оставь изменения в рабочем дереве (worker соберёт патч сам).
- В отчёте: хвост `make check`, время прогона `tests/test_worker.py`, как включить 2
  слота на хосте.
