# T5 — API для дашборда: чтение, лента лога, статистика, вход из браузера

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 3. Опирается на T3b (`events`,
`workers`) и T4 (слоты). Живой поток (SSE) — отдельный тикет T5b; UI — T6/T7.
Здесь: только GET-эндпоинты, разбор `run.log`, вход из браузера и защита.

## 1. Разбор `run.log` — новый модуль `src/agentbus/runlog.py`

`run.log` — JSON-события OpenCode по строке. Реальные типы (см. любой
`.agentbus/cage-claude/read/*/run.log`):
- `step_start`;
- `text` — `part.text`, `part.time.end` (выводить только завершённые);
- `tool_use` — `part.tool` (`shell`, `edit`, `read`, `write`, …), `part.state.status`,
  `part.state.input` (dict);
- `step_finish` — `part.tokens {input, output, reasoning, cache{read, write}}`, `part.cost`;
- `error`; нераспознанные строки и не-JSON.

`parse_lines(lines: Iterable[str], start: int = 0) -> list[dict]` — элемент на строку,
которую стоит показать:

```
{"line": n, "ts": <ms или null>, "type": "tool|text|step|error|raw",
 "tool": "shell", "status": "completed", "summary": "make check", "detail": <исходный JSON-объект>}
```

`summary` для `tool`: `input.command` для shell; `input.filePath`/`input.path` для
файловых; иначе первое строковое значение input; всё обрезается до 200 символов.
Для `text` — текст до 500 символов; для `step` (`step_finish`) — `"tokens in/out/cache"`.
`step_start` пропускается. Функция не падает ни на какой строке.

## 2. Хранилище чтения (`src/agentbus/store.py`)

Все SQL — здесь (как сейчас). Функции:
- `overview(conn, lease_ttl_seconds)` → `workers` (как `list_workers`), `queues`:
  счётчики `queued`/`leased` по `recipient`, `awaiting_review`: число `result`-сообщений
  в `queued` по получателю (это ящики сессий), `recent_events`: последние 20.
- `mailboxes(conn)` → по каждому отправителю задач (`sender` сообщений kind `task`):
  `tasks`, `in_work` (треды с `leased`), `awaiting_review`, `accepted` (результаты с
  `meta->>'state_note'` like `accept%`), `failed`, `last_activity`.
- `list_threads(conn, *, mailbox=None, repo=None, state=None, q=None, limit=50, offset=0)`
  → тред: `id`, `repo`, `created_by`, `ticket` (`meta.ticket` первой задачи), `title`
  (первая строка тела первой задачи, ≤160), `messages`, `attempts` (max `attempt`),
  `last_kind`, `last_state`, `updated_at`, `model` (из последнего результата). Фильтр
  `state`: `active` (есть queued/leased), `review` (последний — result в queued),
  `done`, `failed`. `q` — `ilike` по телам сообщений треда. Сортировка по `updated_at desc`.
- `thread_timeline(conn, thread_id)` → `thread`, `messages` (все поля), `events`.
- `stats(conn, group)`; `group ∈ {mailbox, repo, model}`; на группу:
  `tickets` (треды с задачей), `results`, `accepted_first_review` (треды, где первый
  результат принят без вердикта между — `state_note like 'accept%'` у первого result),
  `rework_verdicts` (вердикты с `meta.decision = 'rework'`), `timeouts`
  (`meta.timeout = true` у результатов), `failed`, `median_queue_seconds`
  (`leased.at − created.at` по событиям задач и fix), `median_run_seconds`
  (`created` результата − `leased` его родителя), `tokens_input`, `tokens_output`
  (сумма `meta.usage.tokens.*` результатов). Пустые значения — `null`, не падать.

## 3. Эндпоинты (`src/agentbus/api.py`, все GET, под guard)

- `GET /v1/overview`
- `GET /v1/mailboxes`
- `GET /v1/threads?mailbox=&repo=&state=&q=&limit=(≤200)&offset=`
- `GET /v1/threads/{id}/timeline` — плюс у каждого сообщения `artifacts`: список файлов,
  реально лежащих в `<artifacts_dir>/<message_id>/`. 404 на неизвестный тред.
- `GET /v1/messages/{id}/log?after=<line>` — лента `runlog.parse_lines` с курсора
  `after` (номер строки, по умолчанию 0) + `next` (номер следующей строки) + `running`
  (bool: сообщение в `leased`). Где искать `run.log`: `<artifacts_dir>/<id>/run.log`;
  если нет — у ответа на это сообщение (`parent_id = id`, kind `result`):
  `<artifacts_dir>/<reply_id>/run.log`. Нет файла → пустой список, `next = after`.
  Не читать больше 2 МБ за запрос.
- `GET /v1/stats?group=mailbox|repo|model` (иначе 422).

## 4. Вход из браузера и защита

- `config.Settings`: `allowed_hosts: tuple[str, ...]` из `AGENTBUS_ALLOWED_HOSTS`
  (через запятую), по умолчанию `127.0.0.1:<port>,localhost:<port>`. Поле — со значением
  по умолчанию, чтобы существующие конструкторы `Settings` не ломались.
- Middleware: запрос с заголовком `Host` не из списка → 421 (защита от DNS
  rebinding). Тесты: в фикстуре добавить `testserver`.
- `GET /ui/login?token=...` — при верном токене ставит cookie `agentbus_token`
  (HttpOnly, SameSite=Strict, Path=/) и редиректит на `/ui/`; при неверном — 401.
- Guard принимает cookie **только для GET**; POST/PUT — только `Authorization: Bearer`
  (как сейчас). Так браузерная сессия не может ничего изменить.
- `GET /ui/` и статика из `src/agentbus/ui/` (`StaticFiles`, `html=True`); без cookie
  страница всё равно отдаётся (это просто HTML), данные — нет. В `ui/index.html` пока
  заглушка: заголовок «agentbus» и текст «UI — T6». `pyproject` / пакетные данные
  поправить так, чтобы каталог `ui/` находился при запуске из checkout (`uv run`).

## 5. Тесты — новые `tests/test_runlog.py`, `tests/test_dashboard_api.py`

`test_runlog.py`:
1. Набор строк каждого типа (+ не-JSON, + битый JSON) → ожидаемые элементы, `step_start`
   пропущен, незавершённый `text` пропущен, summary для shell/edit/прочих.
2. `start` сдвигает нумерацию `line`.

`test_dashboard_api.py` (через `client`, данные создавать через API/`store`):
3. `overview`: очередь и `awaiting_review` после task → lease → reply.
4. `mailboxes`: два отправителя, у одного принятый результат
   (`state` с note `accept: ok`) → верные `accepted`, `awaiting_review`.
5. `threads`: фильтры `mailbox`, `state=review`, `q`; `ticket` и `title`.
6. `timeline`: сообщения и события в порядке, `artifacts` из временного каталога; 404.
7. `log`: файл у задачи → лента и `next`; повтор с `after=next` → пусто; файл только у
   ответа → находится; `running` true для leased.
8. `stats` по `mailbox` и `model` на подготовленных данных (один принят с первого ревью,
   один после вердикта rework); неверный `group` → 422.
9. Host: чужой Host → 421; `/ui/login` с верным токеном ставит cookie, после чего
   `GET /v1/overview` без Bearer → 200, а `POST /v1/messages` с одной cookie → 401;
   неверный токен → 401.
