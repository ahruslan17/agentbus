# T5b — живой поток событий (SSE) для дашборда

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 3. Опирается на T3b
(`pg_notify('agentbus', {"event_id","kind","message_id","thread_id"})`) и T5 (вход по
cookie, `allowed_hosts`).

## Что сделать

### 1. Слушатель (`src/agentbus/live.py`, новый)

- Класс `Hub`: **одно** соединение psycopg с `LISTEN agentbus` на весь процесс API, в
  отдельном потоке (`conn.notifies(timeout=...)` в цикле), запускается лениво при
  первом подписчике и останавливается при `shutdown` приложения.
- Подписчик — `asyncio.Queue(maxsize=1000)`; `Hub.subscribe()` / `unsubscribe()`.
  Раздача из потока в event loop через `loop.call_soon_threadsafe`. Переполненная
  очередь подписчика → подписчик отключается (лог), остальные не страдают.
- Обрыв соединения с БД → переподключение с паузой 2 с; подписчики получают событие
  `{"type": "reconnected"}` (клиенту стоит перечитать `/v1/overview`).

### 2. Эндпоинт (`src/agentbus/api.py`)

`GET /v1/stream` (под guard, cookie подходит — это GET):
- `text/event-stream`, заголовки `Cache-Control: no-cache`, `X-Accel-Buffering: no`;
- первым сообщением — `event: hello` с `{"last_event_id": <max(id) из events>}`;
- каждое уведомление — `id: <event_id>`, `event: agentbus`, `data: <json уведомления>`;
- комментарий-keepalive `: ping` каждые 15 с;
- заголовок запроса `Last-Event-ID` → перед живыми сначала догнать пропущенное через
  `store.recent_events(after_id=...)` (до 500), без дублей с живыми;
- отключение клиента освобождает подписку.

### 2b. Хвост лога без обрыва (`src/agentbus/api.py`, `_read_log_lines`)

Пока исполнитель пишет `run.log`, последняя строка файла может быть недописана (нет
`\n`). Сейчас она уходит в ленту как `raw`, а курсор `next` её проскакивает — строка
теряется. Нужно: последнюю строку без `\n` не отдавать и не учитывать в `next`
(её отдаст следующий запрос, когда она допишется). Тест в `tests/test_dashboard_api.py`:
файл, оканчивающийся недописанной JSON-строкой → её нет в `lines`, `next` указывает на
неё; после дописывания `\n` запрос с `after=next` её возвращает.

### 3. Тесты — `tests/test_live.py`

1. `Hub` с реальным Postgres: подписчик получает уведомление после создания сообщения
   через `store` в другом соединении (таймаут ожидания 5 с).
2. Два подписчика получают одно и то же; отписка одного не мешает другому.
3. Переполнение очереди одного подписчика отключает только его.
4. `/v1/stream` через `TestClient` (stream=True): `hello`, затем событие после
   `POST /v1/messages`; читать с таймаутом, тест не должен висеть.
5. `Last-Event-ID`: создать 3 сообщения, подключиться с id первого события →
   сначала приходят пропущенные, по возрастанию, без дублей.
6. Keepalive: интервал выносится в настройку/параметр, в тесте 0.2 с → `: ping` приходит.

- Не добавлять зависимостей.
