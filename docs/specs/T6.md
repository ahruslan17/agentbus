# T6 — UI: каркас, «Сейчас», «Тред»

Контекст: `docs/plan-parallel-and-dashboard.md`, раздел 3 («Страницы»). Опирается на T5
(GET-эндпоинты, cookie-вход, статика из `src/agentbus/ui/`). T5b (SSE) может ещё не быть
в master — UI обязан работать и без него.

Параллельно с T6 идёт T7 (страницы «Ящики», «История», «Статистика»). Чтобы не было
конфликтов, **T6 создаёт каркас и заглушки страниц T7**, а T7 меняет только свои файлы.

## Технически

- Без сборки, без npm, без внешних CDN (дашборд локальный и должен работать офлайн):
  `index.html`, `style.css`, `app.js`, по файлу на страницу. ES-модули
  (`<script type="module">`), только стандартный браузерный JS.
- Хэш-роутинг: `#/now` (по умолчанию), `#/thread/<thread_id>`, `#/mailboxes`,
  `#/history`, `#/stats`.
- Регистрация страниц: `app.js` экспортирует `registerPage(name, {title, render})`;
  `render(root, params, ctx)` получает контейнер, параметры маршрута и `ctx` с
  `api(path)` (fetch + JSON + обработка 401), `onLive(fn)` (подписка на живые события,
  см. ниже), `link(path)`, форматтеры (`fmtDuration`, `fmtTime`, `fmtTokens`).
  `index.html` подключает **все пять** страниц.
- Создать заглушки `pages/mailboxes.js`, `pages/history.js`, `pages/stats.js`: каждая
  регистрирует страницу с текстом «скоро — T7». Их содержимое T7 заменит.
- 401 от API → экран входа: поле для токена и кнопка, ведущая на
  `/ui/login?token=...`. Токен нигде не сохраняется в JS.
- Живые обновления: `ctx.onLive(fn)` — если `GET /v1/stream` отвечает (EventSource
  открылся), вызывать `fn(event)` на каждое событие; иначе — fallback: опрос
  `/v1/events?after=<последний id>` раз в 3 с и вызов `fn` на каждое новое. Подписки
  снимаются при смене страницы.
- Тема: светлая и тёмная по `prefers-color-scheme`; цвета — CSS-переменные в `:root`.
  Ширина от 360 px до широкого экрана без горизонтального скролла страницы (диффы и
  логи скроллятся внутри своих блоков). Моноширинный шрифт для id, диффов, логов.
- Шапка: «agentbus», навигация по пяти страницам, индикатор связи (live / опрос /
  нет связи).

## Страница «Сейчас» (`pages/now.js`)

Данные: `/v1/overview`, обновление по живым событиям (не чаще раза в секунду) и раз в
10 с на всякий случай.

- **Слоты** — карточка на каждый `worker`: id (`local-opencode#0`), состояние
  (idle/busy/stopping/stopped/stale — `stale` выделить), модель, harness. Для `busy`:
  тикет и тред (ссылка), сколько идёт (от `leased` события / `heartbeat`), последние 3
  строки ленты из `/v1/messages/{message_id}/log` (обновлять раз в 2 с, пока карточка
  видна, через курсор `after`).
- **Очереди** — по получателям: queued / leased; по ящикам сессий: ждут ревью.
- **Последние события** — 20 строк: время, kind, тред (ссылка), actor.

## Страница «Тред» (`pages/thread.js`)

Данные: `/v1/threads/{id}/timeline`.

- Заголовок: тикет, репозиторий, ветка, кто создал, состояние.
- Таймлайн сообщений по порядку: kind (task/result/verdict/fix/note), отправитель,
  время, attempt, тело (markdown не рендерить — `pre-wrap`; длинное — свернуть до 20
  строк с «показать всё»). Решение вердикта (`meta.decision`) и `state_note` — бейджем.
- У результата: длительность, токены (`meta.usage`), модель, `checks` (ok/fail + хвост
  по клику), список артефактов.
- **Дифф** (`/v1/messages/{id}/artifact?name=patch.diff`): свой рендер unified diff —
  по файлам, сворачиваемые, строки `+`/`-`/контекст разными цветами, номера строк.
  Большой дифф (> 3000 строк) — по файлам свёрнуто по умолчанию.
- **Лента исполнителя** (`/v1/messages/{task_id}/log`): строки `время  tool  summary
  status`, текст агента отдельным стилем, клик — сырой JSON. Если сообщение `running`
  — дописывать новые строки раз в 2 с через курсор `after` и автоскролл, если
  пользователь внизу.
- События треда — компактной полосой под таймлайном.

## Проверка

- `tests/test_ui.py`: `/ui/` отдаёт `index.html`, в нём подключены все пять страниц,
  каждый подключённый файл отдаётся 200 с правильным content-type; `app.js` содержит
  `registerPage`.
- Если в системе есть `node`, `node --check` каждого `.js` (в тесте — `skip`, если node
  нет).
- Вручную в отчёте: запустить API на тестовой БД с данными из тестов (или с реальной —
  только чтение), открыть `/ui/` и описать, что видно на «Сейчас» и «Треде»; если
  браузера нет — `curl` всех файлов и вывод `/v1/overview`.

## Чего НЕ делать

- Не трогать Python-код, кроме `tests/test_ui.py` (если нужен фикс в API — описать в
  отчёте, не делать).
- Никаких зависимостей, CDN, шрифтов из сети.
- Никаких кнопок, меняющих состояние (только чтение).

- `make check` зелёный, `tests/test_ui.py` проходит.
- Изменены только файлы из списка. Не коммить.
- В отчёте: дерево `ui/`, размеры файлов, описание проверки вручную.
