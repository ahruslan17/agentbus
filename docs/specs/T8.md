## 1. `skills/agentbus/SKILL.md` — переписать под новую модель

Это инструкция для Claude в VM; сейчас она описывает один ящик и одного исполнителя
(«Параллельно ставить бессмысленно» — больше не так). Должно быть:

- **Ящик.** `cb` выбирает ящик: `AGENTBUS_SHARE` → `AGENTBUS_MAILBOX` → git-корень cwd
  (`claude-<repo>`) → `cage-claude`. Рекомендация: задавать `AGENTBUS_MAILBOX` явно в
  каждой команде или в env сессии, чтобы ответы не уехали в другой ящик при смене cwd;
  `cb env` показывает, какой выбран.
- **Отправка.** `cb send` печатает `id` и `thread_id` (по квитанции); `--wait-id`.
  Обязательные поля `meta`: `ticket`, `acceptance`, `scope_files`; `checks` по
  необходимости; `checks_parallel` — когда тесты проекта изолированы.
- **Параллельно.** Пул исполнителей (`AGENTBUS_WORKER_SLOTS`). Независимые тикеты
  (непересекающиеся `scope_files`) отправлять сразу, каждый в новом треде; зависимый —
  только после merge предыдущего. Справедливость между сессиями и один исполнитель на
  тред обеспечивает очередь.
- **Ожидание.** `cb wait <id...> [--all] [--timeout N]` вместо опроса inbox.
- **Ревью.** Смотреть дифф (`cb patch` — накопленный дифф треда, `attempt.diff` —
  последняя попытка), `meta.checks`, `meta.usage`. `exit_code 143` = исполнитель убит
  сигналом — отправить вердикт «продолжи с текущего состояния».
- **Вердикт / принятие.** `cb reply <id> --kind verdict` (по умолчанию
  `decision=rework`), `cb accept <id> [--note]` — принять.
- **Merge.** Worker коммитит каждую попытку в ветку `agentbus/<thread_id>` —
  мержить веткой (`git merge --ff-only` или обычный merge), не патчем. Исполнитель не
  пушит и не мержит.
- **Нельзя из VM:** `git worktree prune` в репозиториях исполнителя (worktree лежат на
  хосте в `~/.local/state/agentbus/worktrees`, в VM они видны как `prunable`).
- **Дашборд:** `http://127.0.0.1:8787/ui/login?token=...` на хосте.
- Убрать устаревший раздел «Ограничения».

## 3. Уборка — `src/agentbus/prune.py` (новый), `make prune`

`python -m agentbus.prune [--keep N] [--dry-run] [--delete-merged-branches]`:
- закрытый тред = в нём нет сообщений `queued`/`leased`;
- оставить N последних закрытых тредов (по последнему `updated_at`, по умолчанию 50);
  для остальных: удалить `<state_dir>/worktrees/<thread>` через
  `git -C <repo> worktree remove --force`, каталоги артефактов его сообщений
  (`<artifacts_dir>/<message_id>`), `<state_dir>/threads/<thread>.json`;
- с `--delete-merged-branches` — удалить ветку `agentbus/<thread>`, только если она
  целиком влита в `master`/`main` репозитория (`git branch -d`, не `-D`);
- строки в БД не трогать; `--dry-run` печатает план и ничего не делает;
- репозиторий берётся из `threads.repo`; вне `AGENTBUS_REPOS` — пропустить с
  предупреждением.
- `Makefile`: `prune` (`KEEP ?= 50`, передаёт `--keep $(KEEP)`).

## 4. Smoke на два ящика — `tests/smoke_pool.sh`, `make smoke-pool`

Без модели, через `ab` и HTTP, как `tests/smoke.sh`: два отправителя (`smoke-a`,
`smoke-b`) кладут по задаче в разные треды; два lease с owner `local-opencode#0` и `#1`
выдают обе (разные треды) — проверка, что третий lease пуст; оба отвечают; каждая
сторона видит ответ только на свою задачу (`/v1/inbox/smoke-a`, `/v1/inbox/smoke-b`);
`/v1/overview` и `/v1/threads?mailbox=smoke-a` отражают это; в конце
`smoke pool ok`. Если `ab` не умеет передать `owner` — добавить флаг `--owner` в
`bin/ab`.
