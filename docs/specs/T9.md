# T9 — prune не трогает worktree с несохранённой работой

Контекст: ревью T8. `make prune --dry-run` на реальном state планирует удалить 26 worktree
старых тредов. Треды до T4b не коммитились worker'ом: изменения исполнителя лежат в
worktree незакоммиченными (часто staged). `git worktree remove --force` их уничтожит, и
если результат не был влит патчем — работа потеряна.

## Что сделать (`src/agentbus/prune.py`)

Worktree удаляется, только если в нём **нет несохранённой работы**:
- `git -C <worktree> status --porcelain --untracked-files=normal` пустой (игнорируемое
  вроде `.venv/` не считается), и
- его ветка не содержит коммитов, которых нет в `master`/`main` репозитория, **или**
  эти коммиты есть в какой-то ещё ветке (ветка треда сама сохраняет коммиты — значит,
  удаление worktree их не теряет; проверка нужна только для detached HEAD).
  Проще: если HEAD worktree — detached и не является предком `master`/`main` —
  пропустить.

Иначе — в `skipped` с причиной (`uncommitted changes: N files` / `detached HEAD with
unmerged commits`). Артефакты и base-файл такого треда тоже не удалять (вместе с
worktree это единственное, что позволит восстановить работу).

Флаг `--force-dirty` отключает проверку (удаляет как сейчас); в `--dry-run` печатать,
что было бы пропущено без флага.

Итоговая строка плана: добавить число пропущенных грязных worktree.

## Тесты (`tests/test_prune.py`)

1. Закрытый тред с незакоммиченным файлом в worktree → worktree, артефакты и base-файл
   остаются, в `skipped` причина с числом файлов.
2. То же со staged-изменением.
3. Только игнорируемые файлы (`.venv/` в `.gitignore`) → удаляется.
4. `--force-dirty` → удаляется.
5. Detached HEAD с коммитом не из master → пропуск; detached HEAD на коммите master →
   удаляется.
6. Существующие 4 теста не ослаблены.

## Критерии приёмки

- `make check` зелёный. Изменены только файлы из списка. Не коммитить.
- В отчёте: вывод `make prune PRUNE_ARGS=--dry-run` на реальном state — сколько
  worktree теперь пропускается как грязные.
